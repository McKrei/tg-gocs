# Family Docs Agent Bot — PRD

> Этот документ описывает исходные требования к продукту. Актуальное техническое описание реализации см. в [docs/architecture.md](docs/architecture.md).

---

## 1. Описание проекта

Telegram-бот для семейного использования. Предназначен для классификации, переименования, сохранения и последующего семантического поиска документов (фотографии, PDF, сканы).

---

## 2. Стек технологий

| Компонент | Решение |
|---|---|
| Язык | Python 3.13+ |
| Менеджер зависимостей | `uv` |
| Telegram-фреймворк | `aiogram 3.x`, FSM |
| Конфигурация | `pydantic-settings` |
| БД | SQLite + SQLAlchemy 2.0 (async, `aiosqlite`) |
| Векторный поиск | `sqlite-vec` |
| LLM | `google/gemini-3.5-flash` через OpenRouter |
| Эмбеддинги | `google/gemini-embedding-2` через OpenRouter |
| Google Drive | `google-api-python-client`, OAuth 2.0 |
| Инфраструктура | Docker (один контейнер), Makefile |

## 3. Пользовательские сценарии

### Flow 1: Умный приём и сохранение документа

1. Пользователь вводит `/add`, бот переходит в режим ожидания файла.
2. Пользователь отправляет фото или PDF (можно несколько — склеятся в PDF).
3. Бот сразу анализирует через Gemini Flash (Vision), присылает черновик:
   > *«Вижу [Медицинский полис]. Предлагаю: Медицина/Жена / Полис_ОМС_2026.pdf»*
   > Кнопки: **[✅ Сохранить]** / **[✏️ Редактировать]** / **[❌ Отменить]**
4. При необходимости пользователь корректирует текстом — бот обновляет черновик.
5. При подтверждении: файл сохраняется локально (опционально) и в Google Drive, метаданные + эмбеддинг записываются в SQLite.

### Flow 2: Семантический поиск

1. Пользователь вводит `/search паспорт жены` или просто `/search`.
2. Бот генерирует вектор запроса, ищет по sqlite-vec (KNN).
3. Gemini Flash проводит re-ranking топ-5 результатов.
4. Бот отправляет файл в чат + ссылку на Google Drive.

### Flow 3: Inbox-обработка

1. Пользователь загружает файлы напрямую в inbox-папку Google Drive.
2. По команде `/inbox` бот скачивает файлы по одному и предлагает подтвердить метаданные.
3. После подтверждения файл перемещается в основную структуру Drive и индексируется в БД.

### Flow 4: Синхронизация Drive → БД

1. `/sync` — рекурсивный обход GDRIVE_ROOT_FOLDER_ID.
2. Новые файлы классифицируются и добавляются в БД.
3. Файлы, удалённые из Drive, удаляются из БД.

## 4. Управление контекстом (FSM)

- **`DocumentProcessingStates`**: `waiting_file` → `confirming` → `waiting_query`
- **`InboxStates`**: `processing` → `confirming`
- **Session TTL**: если пользователь «завис» с незавершённой сессией — сброс через `SESSION_TTL_SECONDS` (по умолчанию 30 мин).
- **Принудительный сброс**: `/cancel` или `/reset`.

---

## 5. Инструменты агента (Tool Calling)

Агент работает в двух режимах:
- **full** — полный набор инструментов (при сохранении через бота)
- **classify_only** — только read-only инструменты (inbox, sync)

| Инструмент | Режим | Назначение |
|---|---|---|
| `get_directory_tree(path_prefix)` | оба | Дерево папок локального хранилища |
| `create_directory(path)` | full | Создать папку |
| `convert_to_pdf(file_ids, output)` | full | Склеить фото/PDF в один PDF |
| `save_to_local_and_drive(src, dst)` | full | Сохранить файл |
| `vector_search(query, limit)` | оба | Семантический поиск |

## 6. Модель данных

**Таблица `documents`**:

| Поле | Тип | Описание |
|---|---|---|
| `id` | UUID | Первичный ключ |
| `saved_filename` | String | Имя файла |
| `local_path` | String | Путь локальной копии |
| `gdrive_link` | String? | Ссылка в Drive |
| `category` | String | Путь к папке |
| `owner` | String | Владелец (имя или «Общее») |
| `summary` | Text | Описание и реквизиты от LLM |
| `embedding` | BLOB | float32 вектор (768d) |
| `created_at` | DateTime | Дата добавления |

## 7. Развёртывание

- **`uv`** — управление venv, установка пакетов, запуск.
