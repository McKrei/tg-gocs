# Правила разработки проекта Family Docs Agent Bot

## 1. Язык и документирование
- **Важно:** Все комментарии к коду, строки документации (docstrings) и логи должны быть написаны **строго на русском языке**.
- Код (названия переменных, функций, классов) должен быть на английском языке.
- Все ключевые функции, хэндлеры и вспомогательные утилиты должны быть снабжены кратким описанием работы на русском языке.
- **Без воды:** Комментарии должны быть емкими, лаконичными и только там, где они действительно необходимы для понимания логики. Не нужно писать очевидные комментарии к каждой строчке кода.

## 2. Стек технологий и управление проектом
- **Версия Python:** Python 3.13+.
- **Управление зависимостями:** Использовать исключительно `uv` (управление venv, установка пакетов, запуск).
  - Установка пакетов: `uv add <package_name>`
  - Запуск скриптов/тестов: всегда через `uv run <command>` (например, `uv run python main.py`, `uv run pytest`).
  - **Версии пакетов:** Не пинить версии жестко вручную в `pyproject.toml` без необходимости. Указывать зависимости без жестких версий, чтобы `uv` мог разрешить и установить актуальные версии библиотек.
- **Telegram Bot:** Фреймворк `aiogram 3.x`. Использовать FSM (Finite State Machine) для управления состояниями сессий.
- **Работа с конфигурацией:** Использовать `pydantic-settings`. Конфигурация должна быть разбита на классы (`BotConfig`, `LLMConfig`, `DBConfig`, `StorageConfig`) с валидацией `.env`.
- **База данных:** SQLite + SQLAlchemy 2.0 (асинхронный режим, `aiosqlite`).
- **Векторный поиск:** Использовать `sqlite-vec` (или аналогичное встроенное решение sqlite для векторов) для хранения эмбеддингов.
- **Интеграция с LLM и Google Drive:**
  - LLM: `google/gemini-3.5-flash` через OpenRouter.
  - Embeddings: `google/gemini-embedding-2` через OpenRouter.
  - Google Drive: `google-api-python-client` (авторизация через Service Account `credentials.json`).

## 3. Архитектура и структура проекта
- Исходный код приложения должен располагаться в директории `src/`.
- База данных, временные/локальные файлы и credentials.json должны находиться в директории `data/`.
- Использовать `Makefile` для автоматизации повседневных задач:
  - `make run` — запуск бота в dev-режиме.
  - `make test` — запуск pytest.
  - `make lint` — запуск линтеров (`ruff`, `mypy`).
  - `make format` — форматирование кода с помощью `ruff format`.
  - `make up` — сборка и запуск контейнера через `docker-compose`.

## 4. Качество кода и форматирование
- Использовать `ruff` для быстрого линтинга и форматирования. Настройки ruff должны быть определены в `pyproject.toml`.
- Использовать `mypy` для статической типизации. Все публичные сигнатуры функций должны содержать type-hints.
  - **Важно:** Никогда не использовать встроенный `any` в качестве type hint. Вместо этого импортировать `Any` из `typing`.
  - Для классов настроек `pydantic-settings` при вызове инициализаторов без аргументов (например, `self.bot = BotConfig()`) добавлять комментарий `# type: ignore[call-arg]`, так как mypy считает отсутствующие переменные окружения обязательными аргументами конструктора.
- Писать асинхронный, неблокирующий код. Никаких синхронных блокирующих вызовов (например, `time.sleep` или синхронных запросов) в асинхронных хэндлерах.
- Перед завершением любой задачи **обязательно** прогонять локальные проверки с помощью `make lint` и `make test`.
