# **Product Requirements Document (PRD): Family Docs Agent Bot**

## **1\. Описание проекта**

Telegram-бот (агент) для семейного использования. Предназначен для классификации, переименования, сохранения и последующего семантического поиска документов (фото, PDF, сканы).

## **2\. Стек технологий**

* **Язык:** Python 3.12+  
* **Управление зависимостями:** uv (сборка, линтинг, запуск).  
* **Фреймворк:** aiogram 3.x (асинхронный Telegram бот, FSM для управления состояниями).  
* **Конфигурация:** pydantic-settings (иерархия классов настроек, валидация .env).  
* **БД:** SQLite \+ SQLAlchemy 2.0 (асинхронный драйвер). Векторный поиск: sqlite-vec (предпочтительно) или локальный инстанс Chroma/Qdrant.  
* **LLM Architecture:** Единая мультимодальная модель google/gemini-3.5-flash (через OpenRouter). Выполняет роли: Vision (анализ документов), Chat (общение), Agent (вызов инструментов).  
* **Embeddings:** Мультимодальная модель google/gemini-embedding-2 (через OpenRouter).  
* **Google Drive API:** Библиотека google-api-python-client (или асинхронные аналоги) для работы с облаком.  
* **Инфраструктура:** Docker (один контейнер, volumes для кода, БД и локальных файлов), Makefile для автоматизации рутины.  
* **Стиль кода:** Весь код должен быть документирован, комментарии и docstrings строго на русском языке.

## **3\. Пользовательские сценарии (User Flows)**

### **Flow 1: Умный прием и сохранение документа (Smart Multi-file flow)**

1. Пользователь отправляет файл (фото или PDF).  
2. Бот сохраняет его во временную папку, включает состояние FSM: processing\_document.  
3. **Немедленный анализ:** Бот сразу отправляет файл в gemini-3.5-flash.  
4. Бот присылает ответ (Draft предложения):  
   * *"Вижу \[Медицинский полис\]. Предлагаю категорию Медицина/Жена/Полис\_ОМС\_2026.pdf. Если это все — жми сохранить. Если есть еще страницы — просто кидай их сюда."*  
   * Inline кнопки: \[Сохранить так\], \[Склеить и сохранить\] (если фото несколько), \[Выбрать другую папку\], \[Отмена\].  
5. **Ветвление логики в состоянии ожидания:**  
   * **Пользователь шлет еще фото/файлы:** Бот молча принимает их, добавляет в текущую пачку (context), при необходимости обновляет Draft предложения (например: *"Понял, теперь это 3 страницы. Склеим в один PDF?"*).  
   * **Пользователь пишет текст (корректировка):** Например, *"Нет, это полис мужа, назови просто полис"*. Модель понимает контекст, обновляет JSON с метаданными и присылает обновленный Draft.  
   * **Пользователь нажимает \[Сохранить...\]:** Переход к шагу 6\.  
6. Вызываются инструменты сохранения (Agent Tools):  
   * convert\_to\_pdf (если нужно склеить фото).  
   * save\_to\_local\_and\_drive (сохранение на SSD \+ в Google Drive).  
   * Запись путей и векторизованного summary (через gemini-embedding-2) в SQLite.  
7. Уведомление об успехе. Очистка временных файлов, сброс FSM контекста.

### **Flow 2: Поиск документа**

1. Пользователь пишет запрос: *"найди полис жены"*.  
2. Бот генерирует вектор запроса, ищет по БД (sqlite-vec).  
3. Модель gemini-3.5-flash фильтрует результаты векторного поиска и формирует ответ.  
4. Выдает релевантный документ (отправляет сам файл в чат \+ ссылку на GDrive).

## **4\. Архитектура Агента и Инструменты**

### **4.1. Управление контекстом (Session Management)**

* **Динамический контекст:** Пока пользователь в состоянии processing\_document, все файлы и текст складываются в массив сообщений (FSM storage).  
* **Таймаут (TTL):** Если пользователь начал отправлять файлы и пропал (например, на 30-60 минут), сессия по таймауту сбрасывается, чтобы следующий файл считался новым документом.  
* **Принудительный сброс:** Команда /cancel или /reset для немедленной очистки контекста.

### **4.2. Инструменты Агента (Tool Calling)**

Единая модель имеет доступ к функциям:

1. get\_directory\_tree(path\_prefix: str) \-\> str: Возвращает текущую структуру папок (локально и в GDrive).  
2. create\_directory(path: str) \-\> bool: Создает новую директорию локально и в GDrive.  
3. convert\_to\_pdf(temp\_file\_ids: list, output\_filename: str) \-\> str: Конвертирует массив медиафайлов в единый PDF.  
4. save\_to\_local\_and\_drive(temp\_filepath: str, target\_path: str) \-\> dict: Сохраняет локально и вызывает API гугла. Возвращает ссылку на файл.  
5. vector\_search(query: str, limit: int) \-\> list: Векторный поиск по SQLite.

### **4.3. Интеграция с Google Drive (Механика)**

* **Авторизация:** Происходит через Service Account. Файл credentials.json прокидывается в контейнер через volume.  
* **Корневая папка:** В настройках задается GDRIVE\_ROOT\_FOLDER\_ID — ID папки, внутри которой бот будет создавать всю структуру. Бот имеет доступ редактора к этой папке.  
* **Логика сохранения (save\_to\_local\_and\_drive):**  
  1. Агент передает путь, например Медицина/Жена.  
  2. Скрипт проверяет, существует ли папка Медицина в корневой папке по ID. Если нет — создает, получает ее ID.  
  3. Проверяет подпапку Жена внутри папки Медицина. Если нет — создает.  
  4. Загружает файл в конечную папку.  
  5. Возвращает webViewLink (ссылку для просмотра) для сохранения в БД.

## **5\. Конфигурация и Модель Данных**

### **5.1 Настройки (Pydantic Settings)**

Конфиг должен быть разбит на классы для удобства импорта (в файле config.py):

* BotConfig (токен, список ID админов/семьи).  
* LLMConfig (api key, model\_name="google/gemini-3.5-flash", base\_url).  
* DBConfig (dsn, путь к sqlite).  
* StorageConfig (пути к локальным папкам, путь к credentials.json, GDRIVE\_ROOT\_FOLDER\_ID).

### **5.2 Модель данных (SQLAlchemy)**

**Таблица documents**

* id (UUID)  
* saved\_filename (String)  
* local\_path (String)  
* gdrive\_link (String, nullable)  
* category (String)  
* owner (String)  
* summary (Text)  
* embedding (Vector / BLOB)  
* created\_at (DateTime)

## **6\. Развертывание и Разработка (Developer Experience)**

* **Пакетный менеджер:** uv (uv venv, uv pip install).  
* **Makefile:**  
  * make run — запуск бота в dev-режиме.  
  * make test — запуск pytest.  
  * make lint — запуск ruff/mypy.  
  * make format — автоформатирование (ruff format).  
  * make up — запуск через docker-compose.  
* **Single Container Docker:** Все приложение вместе с SQLite запускается в одном контейнере.  
* **Volumes:**  
  * \-v ./src:/app/src — исходники (для удобной разработки).  
  * \-v ./data:/app/data — БД (sqlite.db), сохраненные локально файлы и credentials.json.
