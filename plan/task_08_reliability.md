# Задача 8 — Надёжность и обработка ошибок

## Статус: ⬜ Не начата

## Предзависимость
✅ Задача 7 выполнена

## Цель
Сделать бота стабильным "навсегда" — он не должен падать ни при каких обстоятельствах.

## Что делаем

### Обработка ошибок LLM
- [ ] Retry с экспоненциальной задержкой (3 попытки)
- [ ] Timeout на запрос (30 сек)
- [ ] Fallback сообщение пользователю при недоступности модели

### Обработка ошибок Google Drive
- [ ] Retry при сетевых ошибках
- [ ] Продолжить работу если Drive недоступен (сохранить только локально)
- [ ] Уведомить пользователя: "Сохранил локально, Drive временно недоступен"

### Валидация входных данных
- [ ] Проверка формата файла (только фото + PDF)
- [ ] Ограничение размера файла (настраивается в конфиге, напр. 50 МБ)
- [ ] Защита от спама: rate limiting на пользователя

### Очистка ресурсов
- [ ] Гарантированная очистка временных файлов (даже при ошибке)
- [ ] Правильный сброс FSM состояния при любом исходе

### Логирование
- [ ] Структурированные логи (уровни: DEBUG, INFO, ERROR)
- [ ] Логировать все ключевые события: получен файл, классифицирован, сохранён, ошибка
- [ ] Не логировать персональные данные

### Тесты
- [ ] `tests/test_reliability.py` — сценарии: LLM упал, Drive недоступен, файл слишком большой, неверный формат

## Критерий готовности

```bash
make test  # все тесты зелёные, включая test_reliability.py
# При ручном тесте: отправить файл 100 МБ → бот вежливо отказывает
# При выключенном интернете → бот сохраняет локально и сообщает об этом
```
